M.09

派生关系与交互规范

场景 / agent 类型 / mode 派生 + 11 项关键交互规范
🔗 同源：AGENTS.md §9.5 + openspec/2026-07-08-restore-scenario-mode-separation 🧠 设计原则：UI 维度保持用户感知层次，后端维度按系统最优建模

1三层 UI 概念

AgentX 的 UI 把"用哪个 agent"拆分为场景（Scene）+ agent 类型（Agent Type）两层，但后端契约仍是单字段 agent_mode。

┌──────────────────────────────────────────────────────────────┐
│  Scene（UI 第 1 层 · 顶部 title bar）                          │
│  ┌───────────────┐    ┌───────────────┐                      │
│  │     Work      │    │    Coding     │                      │
│  └───────────────┘    └───────────────┘                      │
│         │ derive              │ derive                       │
│         ▼ mode==='work'      ▼ mode∈{coding, coding_team}    │
│  ┌────────────────────────────────────────────────────────┐  │
│  │ Agent Type（UI 第 2 层 · 输入框旁 ModeToggle）           │  │
│  │ Work scene  → [Work]                                    │  │
│  │ Coding scene → [Coding Agent] [Coding Team]             │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
                       │ 写入
                       ▼
            stores/agentMode (zustand)
            field: mode ∈ {work, coding, coding_team}
                       │ 通过 ChatRequest 发送
                       ▼
              后端 router.run_router(mode)

2派生对照表

Work 场景

↓ mode = work
ModeToggle 显示：[Work]
单个全能 Supervisor agent，可调用全部工具与子代理。

Coding 场景

↓ mode ∈ {coding, coding_team}
ModeToggle 显示：[Coding Agent] [Coding Team]
Coding 场景不允许 Team 模式被切到 Work 后保留。

4ModeToggle 按 scene 过滤

const OPTIONS_BY_SCENE: Record<Scene, Option[]> = {
  work:   [WORK_OPTION],
  coding: [CODING_OPTION, CODING_TEAM_OPTION],
};

const visibleOptions = OPTIONS_BY_SCENE[scene].filter(o =>
  o.value === "coding_team" ? codingTeamEnabled : true
);

ModeToggle 显示当前 scene 下的 agent 类型列表。当 coding_team_enabled=false 时，隐藏 Team 选项；如果当前 mode=coding_team，需要回退到 coding。

5关键交互规范（11 项）

从代码注释和 OpenSpec 中提炼的 UI 行为约束，所有 AI 代理在讨论前端时应遵守。

1场景 Tab 切换 · scene=work → 强制 mode=work；scene=coding → 保留 mode（work→coding 升级）。见 stores/scene.ts。
2agent 类型选择器 · 位置：输入框旁的 popover，按当前 scene 过滤。Work scene 仅显示 [Work]，Coding scene 显示 [Coding Agent] [Coding Team]。
3命令面板 · 输入 / 触发（含行首或紧跟空白后），↑↓ 导航，Enter 选中，Esc 关闭。
4@mention 面板 · 输入 @ 触发，仅 work 模式有效，coding 模式自动剥离标记。
5用户消息编辑 · hover 用户消息 → 显示 ✏ 按钮 → 点击进入就地编辑 → Enter 提交 / Esc 取消（流式期间禁用编辑）。
6执行轨迹卡片 · 默认折叠，delegation 容器包裹执行轨迹（reasoning + tool-call / tool-call-group）。连续 ≥3 个相同 tool 合并为 ToolCallGroup。
7路由决策可视化 · 路由分类通过 ClassificationCard 独立卡片展示，位于 delegation 之上，包含分类原因。
8危险工具审批 · ApprovalDialog，dangerous_tool 二按钮（拒绝 / 批准）+ 可选倒计时自动批准；directory_extension 三按钮（拒绝 / 本次允许 / 会话内允许）。
9workspace 绑定 · 会话级字段 workspacePath，未设置时回退 Home（桌面目录）。切换会话自动切换 workspace。
10权限模式 · 会话级 permissionMode ∈ {standard, acceptEdits, bypassPermissions}，影响工具调用是否触发审批。
11开发模式 · sidebar 底部开关，开启后 Rust 用 PowerShell 启动 Python 后端保留控制台窗口（方便看日志），重启后端生效。

6字号规范（差异化）

区域字号CSS 变量
用户消息气泡14px--fs-msg-user
系统输出（assistant 主内容）13px--fs-msg-assist
工具调用 / Reasoning / 卡片标题12px--fs-msg-tool
代码块11px--fs-msg-code

用户 14px vs 助手 13px 实现视觉层次；执行轨迹 12px + 更低透明度（opacity 0.45-0.6）+ 浅色背景（bg-subtle）实现"黯淡"分离。
